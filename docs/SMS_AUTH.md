# 短信验证码辅助

2026-10-16用户授权：查询指定本机短信源，为指定手机号自动填写平台短信登录或短信验证。实现位于`collection/sms.py`和`collection/sms_login.py`，已接入当前实际使用的`Job`、`AdditionalJob`及独立微信任务。旧`media_platform/*/login.py`不是本批次入口，不调用其中的Redis取码或滑块求解逻辑。

## 本地配置与接口

`data/sms_auth_config.json`为本机配置（被git忽略，权限0600），保存enabled、endpoint、phone、timeout，可选sim_id/sub_id。它只包含用户指定的短信源与手机号，不存验证码、短信正文或Cookie。关闭enabled即可禁用。

POST固定JSON：`{"data":{"type":1,"page_num":1,"page_size":10}}`。实际调试得到HTTP 200，返回`data`数组，记录字段content、date（Unix毫秒）、name、number、sim_id、sub_id、type等。number按发送号码处理，不能误当收件手机号；此接口没有收件手机字段，短信源与收件手机号由用户配置明确绑定。若记录另有recipient/to_number则额外严格核对；出现多个SIM分区且未指定分区时停止取码。

## 运行规则

- 七平台Cookie缺失时，仅在本任务自有Chrome CDP页面尝试打开登录/短信页签；运行中遇登录或访问限制时，只检查当前自有页面是否已经提供真实短信表单。微信在搜索、正文及搜狗自有弹窗上作同样检查。
- 只操作当前平台的域名白名单。要求短信输入框、发送按钮、提交按钮，以及目标手机号输入框或匹配的掩码手机号。未提供短信表单、手机不匹配、来源不明时不发送或填写。
- 手机号加跨进程锁，多个平台串行申请验证码；每个worker最多一次短信流程。发送前记录内存短信基线和发送时间，只接受此后新到、最多3分钟内、明确包含本平台标识且只有一个验证码的短信。旧码、别的平台、歧义码、未来时间戳全部拒绝。
- 原生点击发送一次，收到匹配新码后填写并提交一次。登录Cookie变化或页面明确成功/微信目标内容恢复后才允许从原断点重入一次；仅填入验证码不算登录成功。没有成功、超时、接口异常或手机忙均记录固定错误码并暂停，不能自动循环发短信。
- SMS查询、发送及提交仍复用平台单并发RequestGate：七平台结束后至少15秒，微信至少10秒，包括异常；日志仅有固定操作名、时间和状态。
- 不输出、不保存验证码、短信正文或Cookie。接口请求不带浏览器Cookie，不跨地址跟随重定向。验证码只通过本平台原生短信表单提交。
- 图片、滑块、点选等验证仍暂停，绝不调用旧原生登录类的自动验证求解器。HTTP461、访问频繁或接口拒绝等没有短信表单的限制不会因新增短信功能被清除。
- 现有暂停任务不由此功能自动重启；需要恢复时仍按各目录run_id/platforms及用户授权处理。

## 验证范围

使用合成短信验证八个平台标识、旧码/错平台/错手机号/多SIM/歧义码、时间校验、锁、接口异常、日志无短信、图片验证暂停、一次发送/填写及成功确认，另有worker断点只有短信成功才重入的测试。

`SMS_TEST_CDP=1`测试只连接已有Chrome CDP，在自建空白测试页验证真实DOM短信输入、倒计时及图片验证识别，不发送短信、不操作用户页面。真实接口已查通；不能将接口可达、合成测试或表单识别说成八个平台都已完成真实短信登录。
